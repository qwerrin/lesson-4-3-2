# 課題9 LINE Messaging API — メッセージを送る

> LINE Messaging API を利用して、シンプルに「メッセージを送る」機能のを実装してください。
> 【ヒント】公式ラインアカウントを作成する必要があります。（要件の原文ママ）

## 「読み返せない」ところから始める

課題1〜8は、全部おなじ形で締めていた。**送って、別の経路で読み返して、突き合わせる。**

**LINE ではこれが成立しない。** bot が送ったテキストを読み返す API が無いためである
（2026-08-18 に公式 OpenAPI 定義で確認）。

| 探したもの | 結果 |
|---|---|
| `GET /v2/bot/message/{messageId}/content` | **ユーザーが送った**画像・動画・音声専用。bot のテキストは取れない |
| `POST /v2/bot/message/broadcast` の応答 | **空オブジェクト**（`BroadcastResponse` は empty type） |
| `POST /v2/bot/message/push` の応答 | `sentMessages[]` に `id` と `quoteToken` が入る |

ここで選択肢は2つあった。

1. 「送れた（HTTP 200）」で終わりにする
2. **別の物差しを探す**

2を選んだ。理由は課題8と同じで、**確認できない経路を選ぶと、確認の話ができなくなる**から。
課題8では webhook の既定応答が 204 で何も返らないことを理由に Bot 経路を選んだ。
今回も同じ判断で `broadcast` を捨てて `push` を使う。

見つけた物差しは2本ある。

| 物差し | 何を言えるか | どこから取るか |
|---|---|---|
| `totalUsage` の増分 | LINE が**送信対象として1通数えた** | `GET /v2/bot/message/quota/consumption`（**別エンドポイント**） |
| `basicId` / `userId` | **意図したチャネル**を叩いた | `GET /v2/bot/info`（**別エンドポイント**） |

**そして2本とも「何を送ったか」は言わない。** 文面が届いたことは、最後まで機械では確認できない。
だから `verify_push.py` は**合格したときも「確認できないこと」を必ず表示する**。ここがこの課題の主題である。

## LINE 側の準備（全部この課題の利用者の手作業）

**Developers Console からチャネルを直接作る道は塞がれている**（2026-08-19 に実画面で確認）。

> LINE DevelopersコンソールからMessaging APIチャネルを直接作成することはできなくなりました。
> Messaging APIチャネルを作成するには、以下の［LINE公式アカウントを作成する］ボタンから
> LINE公式アカウントを作成した後、LINE Official Account Manager上でMessaging APIの利用を有効にしてください。

順番が決まっているので、そのとおりに進める。

### 1. LINE公式アカウントを作る

<https://entry.line.biz/form/entry/unverified>（未認証アカウント）。
LINEヤフー Business ID でのログインが要る。

**アカウント名は友だちリストとトーク画面に出る＝スクリーンショットに必ず写る。**
「会社・事業者名」も同様に、記事へ載せる範囲を先に決めておく。

### 2. Messaging API を有効にする

**Developers Console ではなく LINE Official Account Manager 側**で行う。
ここでプロバイダーを選ぶと、**Messaging API チャネルが自動生成される**。

### 3. チャネルアクセストークン（長期）を発行する

LINE Developers Console → 対象のチャネル → **「Messaging API設定」タブのいちばん下**。

**ページ最下部までスクロールしないと現れない。** 「チャネル基本設定」タブにあるのは
**チャネルシークレット**で、これは別物である。API のリクエストに載せるのは前者。

Console の UI から手で発行できるのは**長期トークンだけ**（短期・v2.1・stateless はいずれも
API 呼び出しが要る）。長期は**無期限で、チャネルに1本**。

### 4. 送信先のユーザーIDを取る

同じチャネルの **「チャネル基本設定」タブ → 「あなたのユーザーID」**。`U` で始まる。

**「ボットのベーシックID」（`@` で始まる）とは別物。** 取り違えても「IDらしきもの」が
入っているので形の上では気づけない。`common/line_auth.py` はこれを名指しで弾く。

### 5. 自分のスマホで友だち追加する

「Messaging API設定」タブの QR コードを LINE で読む。
**友だち追加していないと push は届かない**（削除済み・ブロック・未友だちは配信失敗）。

ただし「友だちでなければ必ず失敗」ではない。**1:1トークでこちらがメッセージを受けてから
7日以内**なら送れる。条件つきである。

### 資格情報（この課題だけ `.env` を使う）

課題4〜8 は PowerShell の環境変数（`$env:DISCORD_BOT_TOKEN = "..."`）だった。
課題9は **`.env` ファイル ＋ python-dotenv** に変える。同じやり方を9回繰り返しても
新しく分かることが無いのと、**このやり方には前8課題に無い失敗の形がある**ため。

```powershell
copy .env.example .env
```

`.env.example` の2つを埋める。

| 変数 | 値 |
|---|---|
| `LINE_CHANNEL_ACCESS_TOKEN` | 「Messaging API設定」タブ最下部の長期トークン |
| `LINE_USER_ID` | 「チャネル基本設定」タブの「あなたのユーザーID」 |

`.env` は `.gitignore` で追跡対象から外してある。**`.env.example` は追跡する。**

```bash
git check-ignore -v .env          # 無視される（出力あり）
git check-ignore -v .env.example  # 無視されない（出力なし・終了コード 1）
```

> **`.gitignore` の `.env.*` が `.env.example` まで巻き込んでいた。**
> 見本を置いても git に入らず、採点者が値の入れ方を知る手段が消える。
> `!.env.example` の例外を足して直した。

## 設計 — 物差しをどこから取るか

**記録の中の値どうしを比べない。** 自分で書いた値を自分で確かめるトートロジーになる
（課題4・6・7・8で繰り返し踏んだ形）。遠隔検査は必ず API を叩き直す。

| 何を確かめるか | 物差しの出どころ |
|---|---|
| 本文 | **人間がコマンドラインで渡す**（`--text`） |
| 1通ぶん送られたか | `GET /v2/bot/message/quota/consumption` の増分（**送信とは別のエンドポイント**） |
| 意図したチャネルか | `GET /v2/bot/info` の `basicId` / `userId`（**送信とは別のエンドポイント**） |
| message ID | `push` の応答。**これだけは同じ応答の中**なので、単独では証拠にしない |

### 通数は「増えた」ではなく「1 増えた」で見る

多ければ良いわけではない。1通しか送っていないのに 2 増えたなら、別の送信が混ざっている。

遠隔側だけは「記録の値**以上**」で見る。通数は月内で単調に増えるので、送信から検証までの間に
別の送信が入っても正しく通る。減っていたら記録か対象チャネルのどちらかが違う。

### 「確認できないこと」を、合格したときにこそ出す

`verify_push.py` は検査の合否と別に、必ず次を表示する。

```
  --- この検査で確認できないこと ---
  ・本文が届いたかどうか。LINE には bot が送ったテキストを読み返す API が無い → 自分の LINE を目で見て確かめる。
  ・通数の増分は「1通ぶん送信対象になった」までしか言わない。どの文面が数えられたかは言わない。
  ・相手が実際に読んだかどうか。既読の有無を取る API は使っていない。
```

**合格のときに消える作りにしない。** 消えると、読み手が目にするのは常に
「すべて一致しました」になり、確かめていないことが確かめた顔で残る。

### 送る前に確かめられることは、送る前に確かめる

`send_push.py` は push の前に `GET /v2/bot/info` を叩く。ここを後回しにすると
「トークンが無効」と「宛先が違う」が同じように見える。本文が空かどうかも手元で弾く
（**手元で止めれば1通も消費しない**。無料プランは月200通）。

### 記録に生の宛先IDを残さない

`results.json` は public リポジトリに入る。宛先は `U8…9a` の形に伏せる。
伏せ忘れは `verify_push.py` の検査項目として捕まえる（課題8の「伏せ字は呼び出し側に任せない」の記録版）。
`quoteToken` は照合に要らないので**そもそも記録に渡さない**——「受け取ったものは全部書く」を
既定にすると、API に項目が増えた日に黙って漏れる。

## 公式ドキュメントで確認したこと（2026-08-18〜19）

- **リファレンス HTML は折りたたみで本文が取れない。** `/reference/messaging-api/**nojs**/` なら展開版が読める。
  確実なのは公式の OpenAPI 定義 <https://github.com/line/line-openapi/blob/main/messaging-api.yml>
- `push` の応答は `sentMessages[]`（`id` と任意の `quoteToken`）。`broadcast` の応答は**空オブジェクト**
- `GET /v2/bot/info` は `userId` / `basicId` / `displayName` / `chatMode`(`chat`|`bot`) / `markAsReadMode`(`auto`|`manual`) を返す
- `GET /v2/bot/message/quota` は `type` と `value`、`quota/consumption` は `totalUsage`
- **`delivery/push?date=` には `status: unready` がある**＝当日ぶんが集計済みとは限らない。
  **照合に使わない**（空や既定値で返る＝「エラーにならない失敗」になる）
- 無料のコミュニケーションプランは**月200通**。通数は**送信対象になった人数**でカウントされる
  （メッセージ件数ではない）。応答メッセージは課金対象外
- テキストの長さ上限は**自前で検査しない**。このリポジトリで実物で確かめていない数字を
  定数に置くと、LINE 側が変えた日に**正しい送信を拒む**側で壊れる（課題8の `content` と同じ判断）

### 1. `dotenv_values` は存在しないファイルに何も言わない

```
>>> dotenv.dotenv_values("does-not-exist.env")
OrderedDict()
```

**例外も警告も出ない。** `.env` の名前を打ち間違えても、置く場所を間違えても、
読み込みは成功したように見える。失敗が現れるのはずっと後、
「トークンが設定されていません」と言われるときで、そこに**本当の原因が出てこない**。

`common/env_file.py` はこの沈黙を例外に変えるためだけに存在する。

### 2. `interpolate=True`（既定）は `os.environ` から値を持ってくる

```
os.environ["LEAK_PROBE"] = "FROM_OS_ENVIRON"
dotenv_values(path)                     -> {'A': 'FROM_OS_ENVIRON/tail'}
dotenv_values(path, interpolate=False)  -> {'A': '${LEAK_PROBE}/tail'}
```

「`.env` だけを見れば何が渡るか分かる」という設計の前提が、**既定のままでは成立していなかった**。
`interpolate=False` を固定してテストで縛った。

`load_dotenv()` を使わないのも同じ理由で、あちらは既定が `override=False` ＝
**プロセスに残っている古い環境変数のほうが勝つ**。課題4〜8で `$env:` に設定した値が
同じシェルに残っていると、`.env` を直しても効かない。

### 3. `totalUsage` はリアルタイムに増える

ドキュメントに反映タイミングの記載が無かったので測った。

| 時点 | `totalUsage` |
|---|---|
| 送信前 | 0 |
| 送信直後 | **1** |
| +3秒 | 1 |
| +10秒 | 1 |

**遅延しない。** 照合の土台をここに置ける。もし遅延していたら設計を変える必要があった。

### 4. 削除済みの公式アカウントは、一覧では見分けが付かない

LINE Official Account Manager のアカウントリストに「友だち1・管理者・コミュニケーション」と
**普通の行として並んでいた**アカウントが、開いてみると削除済みだった。

設定系の URL は軒並み `403 Forbidden` を返す。**アクセス権の問題に見えて、実際は
「対象が消えている」**。エラーは正直に出ているのに、**エラーの内容が原因を指していない**。

### 5. テストが「落ちてはいるが理由が違う」で素通りした

実装を1か所ずつ壊してテストが落ちるか確かめた。**最初の84か所のうち、11か所が通ってしまった**（素通り7・置換先が見つからない4）。代表的なのは次の4件である。

| 素通りしたもの | なぜ落ちなかったか |
|---|---|
| `.env` 不在の検査 | 消しても「読めたが0件」の検査が代わりに例外を投げる |
| ディレクトリ検査 | 消しても「見つかりません」が代わりに投げる |
| **「確認できないこと」の表示** | `assert "確認できない" in report` が**見出し行**に、`assert "本文" in report` が**別の検査ラベル**「本文が空でない」にヒットしていた |
| 短い宛先の伏せ字 | `!= "U123"` は `U1…23`（元の文字が全部読める）でも真になる |

3つ目がいちばん重い。**この課題の主題を守るための行**が、丸ごと消えても誰も気づかない状態だった。

直し方は2つとも同じで、**例外の型ではなく文言まで見る**／**「違う文字列になった」ではなく
「読めなくなった」を書く**。`task9/tools/mutate.py` に86か所ぶんの壊し方を定義してある。**いま 86/86 kill・素通り0。**

```powershell
.venv\Scripts\python.exe task9\tools\mutate.py
```

課題8で8件踏んだ「落ちてはいるが理由が違う」の再演で、**対象を変えて戻ってきた**。

**素通りの半分は「肩代わり」だった。** 3つ検査を並べると、どれを消しても
残りのどれかが例外を投げる。テストが `例外が出た` しか見ていないと、**3つのうち2つは
いつ消えても分からない**。直したのは実装ではなくテストの側で、**文言まで見る**ようにした。

### 5-1. 検査ツール自身が壊れていて、それを「壊し方が古い」と表示していた

初回に4件が **NOT FOUND**（置換先が見つからない）と出た。壊し方の文字列が古いのだと思ったが、
**実体には全部存在していた**。原因は照合器の側で、このリポジトリの `.py` は全ファイル CRLF
なのに、`newline=""` で読んだ文字列に対して `
` を含むパターンを探していた。
**複数行のパターンは構造的に一度もマッチしない。**

たちが悪いのは、`mutate.py` が **NOT FOUND を素通りと同じ扱い**にしていたこと自体は正しい設計
だった点である。そのおかげで数字は正直に出たが、**「壊し方が悪い」のか「照合器が壊れている」のか
区別が付かない**まま4件が積まれていた。照合と書き込みを LF に正規化して直した。

### 5-2. コマンド例が黙って壊れた

README を書き換えるスクリプトの中で `task9\tools` と書いたところ、`\t` が
**タブ文字に化けて** `task9<TAB>ools\mutate.py` になった。同じ行の `\S` は
「無効なエスケープ」で警告が出たのに、**`\t` は有効なので黙って変換された**。

**警告が出た側は無事で、出なかった側が壊れる。** しかも `check_docs.py` は26項目すべて OK を
返していた。検査項目に無かったため。タブの有無とコマンドが指すファイルの実在を検査に足した
（26 → 31項目）。**この検査を書いている最中にも同じ形で1回踏んだ。**

### 6. モジュール名がタスクをまたいで衝突した

`task9/verify_message.py` を作ったところ、**`task7/verify_message.py` と同名**で
テスト収集が壊れた。前回（課題8）に「タスクをまたいでテストとモジュールの basename は
一意にする」と決めた直後の再演である。`send_push.py` / `verify_push.py` に改名した。

**単体では通って、全体で落ちた。** `task9/tests` だけを回したときは55件すべて通る。
**部分実行は衝突を隠す。**

### 7. URL を推測すると 403 と 404 を踏む

`manager.line.biz` の設定ページも、講座サイトのレッスンページも、パスを当てにいって外した。
