### オプション

| オプション | 意味 |
|---|---|
| `--text` | 挿入する本文を直接指定する |
| `--text-file` | 挿入する本文をファイルから読む（UTF-8） |
| `--title` | ドキュメントのタイトル（既定: ファイル名、それも無ければ「無題のドキュメント」） |
| `--credentials` | OAuth クライアントの JSON（既定: `credentials.json`） |
| `--token` | トークンの保存先（既定: `token.json`） |

`--text` と `--text-file` は**どちらか一方**。両方受け取ると、どちらが使われたかが
実行画面から読み取れなくなる。

## テストで閉じない穴は、実物を1回読んで閉じる

偽の `service` で固定できるのは**呼び方まで**。挿入位置 1 が本当に正しいのか、
`documents.create` に本文を送らなくてよかったのか、日本語がそのまま入るのかは、
143件が全部通っても分からない。

そこで `verify_doc.py` を作った。作ったドキュメントを
**Docs API から読み返して、送ったテキストと突き合わせる**。読むだけで何も変更しない。

```bash
.venv\Scripts\python.exe task2\verify_doc.py <ドキュメントID> --text-file task2\data\sample.txt --title 課題2のドキュメント
```

照合するのは5項目。

| 項目 | 見ているもの |
|---|---|
| ドキュメントIDが一致 | 読み返したのが本当にそのドキュメントか |
| タイトルが一致 | `documents.create` に渡した `title` が反映されたか |
| 本文が一致 | 送った文字列と、読み返した本文が文字単位で同じか |
| 文字数が一致 | 上と別角度。欠けや混入を数でも見る |
| 段落数が一致 | 改行が「文字として入った」だけで段落に分かれていない、を見る |

**平らな文字列の比較だけにしないのが要。** 本文の照合は文字列を1本に潰して比べるので、
改行が段落として反映されたかは見えない。段落数は本文とは別の場所（構造）から数えている。

実測（2026-08-12・上の実行で作ったドキュメント）:

### 値が返ってこなかった項目を OK にしない

`document.get("title", 期待値)` のように既定値を入れると、**照合できなかったケースが
全部「一致」になる**。確かめた気持ちだけが残るので、返らなかったものは NG にする。

`all_ok([])` も `False` にしてある。照合が0件なのに「全部一致」と言わせないため。

## つまずいたところ

### 挿入位置 0 は「本文の外」

新規ドキュメントの本文はインデックス **1** から始まる。0 は `sectionBreak` の位置で、
そこへ挿入しようとすると「段落の中ではない」として 400 で弾かれる。

```python
BODY_START_INDEX = 1
```

### `documents.create` に本文を送っても、黙って無視される

`documents.create` は **`title` 以外を無視する**。本文を一緒に送っても
エラーにならず、成功が返ってきて、中身だけが空になる。
**失敗しないので気づきにくい形。** 本文は必ず `batchUpdate` の `insertText` で入れる。

### ドキュメントの末尾には、消せない改行が1つある

Docs は本文の最後の改行を削除できない。空のドキュメントでも `"\n"` が1つ残る。
つまり読み返した本文は、送った文字列より**常に改行1つぶん長い**。

照合ではこれを1つだけ外してから比べる。ただし「改行で終わっていなかったら
`None` を返して NG」にしてある。`rstrip("\n")` で済ませると、
末尾の改行が2つある場合との区別がつかなくなる。

### CRLF のまま送ると本文に CR が残る

Docs の改行は LF。Windows で書いたファイルをそのまま送ると `\r` が
余分な文字として入り、読み返したときに送った文字列と食い違う。
読み込んだ直後に LF へ揃える。

**照合側も同じ関数で正規化する。** 片方だけ直すと、CRLF のファイルで必ず落ちる。

### BOM を落とさないと1文字目がゴミになる

Windows のメモ帳は UTF-8 に BOM を付けて保存する。`utf-8` で読むと先頭に
`﻿` が残り、ドキュメントの1文字目が見えない文字になる。`utf-8-sig` で読む。

### 課題1のトークンでは動かない

`token.json` は `drive.file` しか持っていない。Docs API には `documents` が要る。
`Credentials.from_authorized_user_file(path, scopes)` に **scopes を渡さない**こと。
渡すとファイルに書かれた実際の権限が引数で上書きされ、権限不足を検出できなくなる。

### 文字数の数えかたが Python と Docs で違う

Docs API のインデックスは **UTF-16 単位**。絵文字などサロゲートペアを含む文字は
2として数えられる。Python の `len()` は1。画面に出す「挿入した文字数」は
Python の文字数で、Docs のインデックスとは一致しないことがある。
挿入位置は先頭固定なので今回は影響しないが、途中に入れる実装にすると効いてくる。
