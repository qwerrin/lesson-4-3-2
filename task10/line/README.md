## 「読み返せない」の続きから始める

課題9の結論はこうだった。

> LINE には bot が送ったテキストを読み返す API が無い（2026-08-18 に公式 OpenAPI 定義で確認）。
> だから `verify_push.py` は、合格したときにも「確認できないこと」を必ず表示する。

**読み返せないなら、送る前に確かめるしかない。** それが課題10で足すものである。

そして調べてみると、**送る前にしか分からないこと**が実際にあった。

| | |
|---|---|
| `push` は**未友だち・ブロックの相手にも 200 を返す** | 送った後では区別が付かない |
| 友だちかどうかを判定する専用の API は**無い** | `GET /v2/bot/profile/{userId}` の **404** だけが手がかり |

課題8から課題9へ持ち込んだ観点に「**エラーにならない失敗を、実装より先にドキュメントで
確認する**」がある。それをそのまま適用したら、この課題の主題が出てきた。

## なぜ「予定の通知」なのか

課題9の記事に、発展アイデアとしてこう書いた。

> **アイデア2：自治体・店舗の「予定日お知らせ」**
> 実在の事例：松山市が令和6年7月1日から、松山市LINE公式アカウントに
> 「ごみ収集日お知らせ機能」を追加している。

自分で「実用的だ」と調べて書いたものを、次の課題で実装する形にした。
**説明が1行で済む**のも選んだ理由である——「その日の予定が、日付が変わったら LINE に届く」。

## 準備（この課題の利用者の手作業）

LINE 側は**課題9のまま**でよい。`.env` の `LINE_CHANNEL_ACCESS_TOKEN` と
`LINE_USER_ID` をそのまま使う。増えるのは Google 側だけである。

### 1. Google Calendar API を有効にする

課題1〜3で作った Google Cloud プロジェクトを開き、

### 2. トークンは専用のファイルに分ける

**ここを共有すると、課題3（Meet）が動かなくなる。**

`common/google_auth.py` は「保存済みトークンのスコープが足りなければ**捨てて取り直す**」
実装になっている。リポジトリのルートにある `token.json` は Meet 用のスコープしか
持っていないので、そこへ Calendar のスコープを要求すると**上書きされる**。

課題5（Gmail）が `token-send.json` と `token-verify.json` に分けたのと同じ理由で、
この課題も専用のファイルを使う。

```

```

`.gitignore` の `token*.json` に該当するので、追跡されない。確認:

```bash
git check-ignore -v task10/line/token-calendar.json
```

### 3. 同意画面を通す

初回の実行で同意画面が開く。要求するスコープは1つだけ。

| スコープ | なぜこれか |
|---|---|
| `https://www.googleapis.com/auth/calendar.readonly` | 予定を**読むだけ**。書き込み権限を取ると、事故で消せる範囲が広がる |

### 4. 自分のスマホで友だち追加されているか

課題9で済んでいるはずだが、**この課題ではそこが検査対象になる**。
友だち解除やブロックをすると、`push` は 200 を返したまま届かなくなる。
その状態を作れば、送信前ガードが働くことを実際に確かめられる。

## 設計

### 送る前に確かめられることは、送る前に確かめる

| 確かめること | 使うもの | 何を防ぐか |
|---|---|---|
| 宛先に届くか | `GET /v2/bot/profile/{userId}` が **404** か | **200 を返すのに届かない**（未友だち・ブロック） |
| 残り通数 | `GET /v2/bot/message/quota` ＋ `/quota/consumption` | 枠切れ |
| 意図したチャネルか | `GET /v2/bot/info` | 課題9から継承 |

### 404 を例外にしない

未友だち・ブロックは**異常ではない**。送る前に分かる、正常な答えである。

例外にすると、呼ぶ側が `try/except` で包むことになり、
**「確かめて届かないと分かった」と「確かめられなかった」が混ざる**。
だから `Reachability` という値にして返す。

一方 **401 や 403 は例外のままにする**。混ぜると、
トークンが切れているのに「相手にブロックされた」と報告することになり、
原因が違うのに同じ直しかたを試すはめになる。

### 「上限なし」を 0 と書かない

`quota` の `value` は、`type` が `limited` のときだけ返る（公式 OpenAPI 定義）。

| `type` | 意味 | `value` |
|---|---|---|
| `limited` | 上限がある | 返る |
| `none` | **無制限** | **省略される** |

無いものを 0 と読むと、**「無制限」が「使い切った」に化ける**。真逆である。
だから残数は `None`（上限なし）と数値を分け、**負の値も丸めない**
——丸めると「あと 0 通」と「12 通ぶん超過している」が同じ表示になる。

### 0 件でも送る

予定が無い日に何も送らないと、**通知が来ないことが「予定なし」なのか
「動いていない」のか、受け取る側から区別できない**。

枠は1通ぶん増えるが、**動いていることが分かる**ほうを取った。

### 日付は外から渡す

`now` を引数で受け取る。実行時刻に依存させると、日付が変わった瞬間に挙動が変わり、
テストで境界を確かめられない。00:01 に走らせて当日ぶんを送る運用なので、
**境界のすぐ内側で動く**ことになる。

`vault_doctor` の `judge_tasks(tasks, now)` と同じ流儀に揃えた。

### 時刻のタイムゾーンを変換しない

`10:00` と出すのは、**カレンダーが返した時刻をそのまま**である。
利用者が画面で見ている時刻と一致するのが、この通知の目的だから。

## 公式ドキュメントで確認したこと（2026-08-20）

実装より先に調べた。**どれもエラーにならず、件数だけ静かに減る**種類の失敗である。

| 項目 | 分かったこと |
|---|---|
| `singleEvents` | 省くと**繰り返し予定が展開されない**。`orderBy=startTime` はこれが真のときだけ使える |
| `start` | 時刻付きは `dateTime`、**終日は `date`**。片方だけ見ると終日予定を丸ごと取りこぼす |
| `timeMin` / `timeMax` | RFC3339 で、**タイムゾーンのオフセットは必須** |
| `quota.value` | `type` が `limited` のときだけ返る |
| `profile` の必須項目 | `userId` と `displayName` だけ。`pictureUrl` / `statusMessage` / `language` は省略されうる（`language` は**利用者がプライバシーポリシーに同意していないと入らない**） |

## 実測でわかったこと（2026-08-20）

### テストが通っていることは、守られていることの証拠にならない

`tools/mutate.py` で 28 か所を1つずつ壊したところ、**最初は 4 か所が素通りした**。
そのうち 2 つは、課題9で踏んだのと同じ形をしていた。

#### 1. 部分一致が、意図しない場所で満たされていた

時刻の整形を確かめるテストが `assert "10:00" in text` だった。
だが整形前の値は `2026-08-21T10:00:00+09:00` で、**この中にも `10:00` は含まれる**。
つまり**整形を全部やめても通る**状態だった。

課題9の「2つの assert が両方とも、無関係な場所の文字列で満たされていた」と同じ原理である。
完全一致と、「含まれてはいけないものの否定」で塞いだ。

#### 2. 防壁を消しても、別の検査が肩代わりしていた

401 を例外にすることを確かめるテストで、`raise_for_line_error` を丸ごと消しても
テストが通ってしまった。**その先の「`userId` が無い」検査が別の例外を投げていた**ためである。
しかも `ApiError` は `LineError` のサブクラスなので、**例外の種類で見ても区別が付かない**。

課題9のセッション記録にこう書いてあった。

> `.env` の検査を3つ並べると、**どれを消しても残りのどれかが例外を投げる**。
> テストが「例外が出た」しか見ていないと、3つのうち2つはいつ消えても分からない。

**まったく同じ形を、次の課題でも踏んだ。**
本文を正常な形にして**防壁を1つだけにする**ことで塞いだ。
「例外が出た」ではなく「**この防壁が働いた**」を見るテストに変えたことになる。
